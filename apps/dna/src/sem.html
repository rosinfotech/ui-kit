Semantics / SEM

A unified system of three-letter codes and name grammars. Any name in the design system — from a color to a component — is assembled from a finite code registry by fixed formulas. This registry is the foundation on which variables, styles and components are built: reading a name, you understand the value’s meaning without opening the file.

Principles

  • A code is three uppercase Latin letters, sometimes with a suffix:
    • BRA/PRM — a family with a slash;
    • FGR_CVB_100 — a compound code;
  • One value — one name. A name answers “what is it”, not “what is it like”;
  • A name reads left to right from general to specific: domain → group → detail;
  • Separators are normalized:
    • / — inside token paths;
    • _ — inside compound codes and set names;
    • = — in variant values;

Space — three layers

The system is spatial:

  • Every component is conceived as three-dimensional, and its elements reside in one of three layers;
  • The layer is the first meaningful segment of a functional color token, e.g.:
    • ABV/DFT/RGL/BGR:
      • ABV, Above, the 1st segment — the layer above the surface, the top layer;
      • DFT, Default, the 2nd segment — the default emphasis;
      • RGL, Regular, the 3rd segment — the regular component state (not hover, for example);
      • BGR, Background, 4-й segment — the background color for the corresponding foreground (ABV/DFT/RGL/FGR);
Code Full name Meaning Examples
ABV Above surface Above the surface. Elevated elements that may cast a shadow downward Button “bodies”, the radio ring and dot, chips etc.
SFC Surface The surface itself, e.g. load-bearing planes Cards, panels, containers
BLW Below surface Below the surface, sunken elements Input wells, grooves

Structure — element, component, composite component

  • An element is an atomic visual part of a component; it resides in exactly one layer — ABV, SFC or BLW;
  • A component is a functional unit of the design system assembled from elements; e.g. a button;
  • A composite component is several components united into a new functional unit; e.g. an input with a label;
A layering example: in a radio button the outer ring and the dot are ABV-layer elements, while the fill between them is an SFC element.

Name grammars

Functional color (the FCL variable)

<layer>/<emphasis>/<state>/<role>
ABV/DFT/RGL/BGR  — the base color of a regular button in its normal state

Absolute color (the CLR token)

<family>/<step>
GRY/200  — gray, step 200 of the 025–1000 scale
BRA/PRM/025  — brand-primary, step 025

Families: BLU, BRN, GRY, GRN, ORG, PNK, RED, VIL, YEL, BRA/PRM, BRA/SEC + the special WHT and BLC. A functional token always references an absolute one: FCL → CLR.

Shadow and gradient

<layer>/<emphasis>/<state>/SHD   e.g. BLW/NEG/HVR/SHD  — the well shadow of an error field on hover
ABV/<PRM|ACC>/<state>/GRD   e.g. ABV/PRM/RGL/GRD  — the primary-action gradient at rest: top light

Typography

TXT/<typeface>/<size>   e.g. TXT/TWR/SZM — Roboto Flex Regular 16
FTY/<role>   e.g. FTY/HD1 — heading 1 (Inter Medium 32)
Roman code Italic code Typeface Weight Description
TWT TIT Thin 100 Hairline; delicate large headings
TWL TIL Light 300 Light; large subheadings, accent text
TWR TIR Regular 400 Regular; body text
TWM TIM Medium 500 Medium; HD2/HD3 headings, buttons
TWB TIB Bold 700 Bold; strong accents
TWE TIE ExtraBold 800 ExtraBold; maximum expressiveness
The italic code is formed by replacing W with I: Thin → TIT, Regular → TIR and so on.

Component set

<COMPONENT_CODE>_<size>   e.g. BTN_SZM — the medium-size button set (height 24)
variant: Emphasis=<code>, State=<code>   e.g. Emphasis=PRM, State=HVR — a primary-action variant on hover

The size suffix is any scale step from XXS to XXL; the control height equals that step’s value in the SPC. Current component sets use SZS, SZM и SZL (16, 24, 32), but the system is not limited to this set.

Step scales

The same step names XXS, SXS, SZS, SZM, SZL, SXL, XXL are used across all scales but mean different values. The step is chosen by meaning, the value comes from the scale table.

Spacings are additionally expressed in rem (0.25 / 0.5 / 1 / 1.5 / 2 / 3 / 4) — base 16 px. The component default radius is RAD/SZS = 12 px.

Naming rules

  • A new code is added only to this page’s registry — a free three-letter combination not colliding with existing ones;
  • A token name is entirely uppercase;
  • Name segments are separated by /, the order is fixed by the domain formula;
  • A component set name is CODE_SZ*;
  • A set variant is described by Key=Value pairs, comma-separated;
  • Compound codes are written with _:
    • FGR_CVB_100 — rule;
    • BRA/PRM — the exception: a family with a slash;
  • A human name is always duplicated by a code (“Emphasis Primary / PRM”);
