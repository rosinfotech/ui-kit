Functional color palette / FCL

The single source of color for components: 263 variables assembled from layers, emphases, states and roles. The values reference absolute palette tokens. Below is the full table of all 90 combinations × 3 roles.

Grammar

<layer>/<emphasis>/<state>/<role>
ABV/DFT/RGL/BGR  →  GRY/200 = #DBDBDB
  • The layer — where the component’s element sits in space (the full registry is in Semantics):
    • ABV — elevated above the surface;
    • SFC — the load-bearing surface;
    • BLW — sunken, “in the well”;
  • The name’s semantic segments:
    • emphasis — the component’s semantic role;
    • state — interaction;
    • role — what we paint:
      • content FGR — text, icon, glyph;
      • frame BRD — stroke, border;
      • BGR — the background color for the foreground: what the FGR lies on;
  • For toggleable components (CHB, TOG, RDB) instead of PRS is used CHD, for inputs INP — states with the suffix _FLD;
  • Roles in each card are shown as color plates with role labels;
Spatiality is complemented by volume: elevated components get the light gradient ABV/…/GRD, for depth — shadows <layer>/…/SHD (ABV casts the shadow down, BLW — into the well).
The role order in cards reflects the layer stacking inside a single element:
  • for ABV and SFC:
    • FGR — the foreground layer: text, graphics;
    • BGR — background for the foreground;
    • BRD — the layer framing the background;
  • for BLW the order is inverted — we go deeper:
    • BRD — the framing layer comes first;
    • FGR — the foreground layer;
    • BGR — the surface layer, the bottom;

How to apply

  • A button (not pressed, regular):
    • background — ABV/DFT/RGL/BGR;
    • text — ABV/DFT/RGL/FGR;
    • border — ABV/DFT/RGL/BRD;
  • An input:
    • the “well” bottom — BLW/DFT/***/BGR;
    • the entered text — BLW/DFT/***/FGR;
  • A card is the surface itself: SFC/DFT/RGL/BGR + shadow SFC/DFT/RGL/SHD;
